# Análisis de Superficie de Ataque y Mitigaciones (Modelo STRIDE)

Este documento detalla los vectores de ataque analizados sobre la API del Gestor de Torneos Esports y las defensas técnicas implementadas y verificadas mediante pruebas automatizadas.

---

Bloqueo del Event Loop en torneos de 1024 equipos. 4. Caída del servicio externo Django.**                              | 1. Rate Limiter por IP devolviendo `429 Too Many Requests` con header `Retry-After`. 2. Límite estricto `express.json({ limit: '100kb' })` devolviendo `413` ante streams gigantes. 3. Delegación de la llave de 1024 participantes y recálculo de ELO a `worker_threads`. 4. Timeout con `AbortSignal.timeout` y política _fail-closed_ (`503`). | `rateLimiter.js`, `app.js`, `src/infra/workers/workerLlaveElo.js` y `src/infra/externos/`                               |

## 2. Prevención de Carreras de Concurrencia y Reintentos Duplicados

1. **Sobrecupo por Inscripciones Simultáneas (Carrera 1):**
   - Mitigado mediante bloqueo pesimista `SELECT * FROM torneos WHERE id = $1 FOR UPDATE` dentro de la transacción de `InscribirEquipo` y la restricción de tabla `CONSTRAINT chk_cupo_no_excedido CHECK (inscriptos_actuales <= cupo_maximo)`.
2. **Doble Reporte Contradictorio y Choque con Arbitraje (Carrera 2):**
   - Mitigado bloqueando la fila del partido con `SELECT * FROM partidos WHERE id = $1 FOR UPDATE` e incrementando atómicamente `version = partidos.version + 1`.
3. **Duplicación de Operaciones por Reintentos de Red (`Idempotency-Key`):**
   - El middleware `idempotencia.js` calcula un hash SHA-256 canónico (`METODO:RUTA:BODY`). Si la misma clave se repite con el mismo payload devuelve la respuesta almacenada con `Idempotent-Replayed: true`; si se reutiliza con otro payload responde `422 Unprocessable Entity`.
